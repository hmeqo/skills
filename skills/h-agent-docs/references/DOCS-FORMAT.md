# DOCS-FORMAT — 项目文档体系格式规范

docs/ 体系每类文档的**模板、职责与边界**，`h-agent-docs` 生成与维护以此为准。

## 组织规则

- **形态**：集合型 → 目录（`topics/`、`specs/`、`adr/`）；单体型 → 文件（`CONTEXT.md`、`architecture.md`）
- **按需生成**：有值得记录的内容才建（纯 CRUD 代码不建）
- **模板节按需**：模板节是覆盖清单（有内容才写、空节省略），非固定表单
- **文档承载代码表达不了的**：意图/决策/坑/术语/导航。源码可读内容（实体清单/字段表/接口清单/符号清单式列表/算法细节）grep/glob 即得，不占文档
- **渐进式披露**：文档间用链接引用（`见 docs/adr/0001-xxx.md`），同一内容只写一处（单一事实来源）
- **长度由内容决定**
- **交叉引用**：文档间引用位置用 `文件:符号名`（行号会过时）

## 职责总览

| 文档 | 职责 | 时机 | 格式权威 |
| --- | --- | --- | --- |
| `AGENTS.md` | 入口：硬规则 + 导航 + 工具链 + 自定义命令 + 维护机制 | 生成 | h-agent-docs SKILL 写作模板 |
| `CONTEXT.md` | 术语权威（IS 非 DOES/混用裁决/关系） | 生成/维护 | `CONTEXT-FORMAT.md` |
| `architecture.md` | 全览骨架：架构声明 + 关键数据流 + 模块导航 + 演进方向 | 生成（调研审查；**新项目/无代码仓库需求未定时不产出，需求确定后规划产出**） | 本文档 |
| `topics/<主题>.md` | **机制/抽象详解**（当前实现的运作/边界/取舍，代码读不出的；**持续维护**） | 实现后沉淀 + 演进更新 | 本文档 |
| `specs/<机制>.md` | **spec 的文档承载**（前瞻设计意图：需求+设计+验收，实现前，按需；也可承载于 GitHub issue，按项目选择） | 规划产出（docs 或 issue，Q1 定案机制） | `SPEC-FORMAT.md` |
| `adr/` | 决策与理由 | 用户主动要求（Q3 定案），三条件触发 | `ADR-FORMAT.md` |
| `docs/research/<主题>.md` | 调研快照（一次性，引用外部来源，详细报告） | h-research 产出（按需） | `RESEARCH-FORMAT.md` |

**追踪/决策机制默认不建，用户主动要求才建（Q1/Q3 定案）——下文相关表述以此为准。**

## 抽象设计内容归属

| 抽象内容 | 承载 |
| --- | --- |
| 需求/边界/验收 | spec（docs/specs/ 或 GitHub issue，Q1 定案机制；非 backlog） |
| 概念/语义 | CONTEXT.md |
| 决策/设计理由 | adr/（按需）+ 代码注释（实现级取舍） |
| 规划/演进 | architecture.md「演进方向」 |
| **机制/抽象（当前实现）** | **topics/<主题>.md（持续维护）** |
| 坑 | AGENTS.md 硬规则（值得防的）+ 代码注释（细节） |
| 全览 | architecture.md |

## architecture.md 模板

```
# architecture

## 架构声明
<一句话：架构类型 + 分层 + 依赖方向>

## 关键数据流
<跨模块、不读全部相关代码看不出整体的流程/数据流>

## 模块导航
| 模块 | 关键文件 | 职责（一句） |

## 演进方向（按需）
<已知的路线/计划中的设计变化>
```

**写法说明**：架构声明是调研提取的现状（用户最初显式决定），审查判断是否符合哲学原则，发现的问题在验收时指出；新项目/无代码仓库需求未定时不写，需求确定后规划产出。数据流用 mermaid 或文本图；每节简短（架构声明一句、模块职责一句）；结构用表格/图承载。

## topics/<主题>.md 模板（持续维护）

```
# <主题>

## 概述
<这个机制/抽象是什么、解决什么>

## 设计
<运作方式/技术架构/关键流程>

## 边界
<做什么/不做什么>

## 取舍与理由
<关键设计取舍 + 为什么>

## 坑/易错点
<现象 + 原因 + 应对>

## 演进方向（按需）
<已知的变化方向>
```

**写法说明**：图文并茂（mermaid 图与文字配合呈现）。随项目演进持续维护（机制变更/重构/新增，`h-agent-docs` 维护模式同轮更新）。

## specs/<机制>.md（spec 的文档承载，前瞻，按需）

spec 模板见 `SPEC-FORMAT.md`（docs/specs 文档与 GitHub issue 共用同一模板）。实现后归档（设计已落地，后续由 topics/ 主题文档承载持续知识）。

**不该有**（所有文档）：实体清单/字段表/接口清单、符号清单式列表、代码逻辑逐段翻译。（交叉引用锚点可用，禁止的是把文档写成符号清单）
